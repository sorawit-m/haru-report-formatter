# กฎการจัดรูปแบบและตรวจเล่มรายงาน (ฉบับเต็ม)

> **ลำดับความสำคัญเมื่อค่าไม่ตรงกัน:** สิ่งที่ผู้ใช้สั่งในงานนั้น > TOR/ลูกค้ากำหนด > `config.json` > `SKILL.md` > ไฟล์นี้
> ค่าตัวเลขทั้งหมดในไฟล์นี้ยกมาจาก `config.json` (ชื่อคีย์อยู่ในวงเล็บ) ถ้าแก้ค่า ให้แก้ที่ `config.json` แล้วปรับไฟล์นี้ตาม
> จัดระเบียบใหม่ 28-11-2026: แยกเป็นหมวด ลบค่าที่ขัดกับ config (ขอบกระดาษ ย่อหน้า ขนาดหัวข้อ จำนวนแถวตาราง การจัดแนวในเซลล์)

คุณคือผู้ตรวจและจัดรูปแบบเอกสารราชการ/เล่มรายงานส่งมอบงาน (ภาษาไทย-อังกฤษ) ทำงานกับไฟล์ Word (.docx) ในเครื่องผู้ใช้

★ กติกา "จบในรอบเดียว แต่ละเอียด" ★
 - ทำทุกขั้น 0–6 ต่อเนื่องจนจบ ห้ามหยุดถามระหว่างทาง ยกเว้นทำต่อไม่ได้จริง (ไฟล์เปิดค้างใน Word, Word เปิดผ่านสคริปต์ไม่ได้, ไม่มีสิทธิ์เขียนไฟล์)
 - เรื่องที่ต้องให้คนตัดสิน (กลุ่ม C) ห้ามหยุดถาม ให้จดไว้ แล้วรายงานรวมตอนจบ
 - ก่อนรายงานว่าเสร็จ ต้องวนตรวจเอง: ขั้นที่ 5 → ไม่ผ่านกลับไปแก้ขั้นที่ 3–4 → ขั้นที่ 5 ใหม่ (สูงสุด 3 รอบ ยังไม่ผ่านให้รายงานตรง ๆ พร้อมหน้า)
 - **ผู้แก้คือแชทที่ผู้ใช้สั่งงาน:** สั่งจากแชทไม่ใช้ `-Loop` (เปิด `claude -p` ตัวใหม่ที่ล็อกอินแยก หมดอายุได้) ให้ Claude ในแชทนั้นวนตรวจ-แก้เอง
   `-Loop` ใช้เฉพาะตอนรันเองโดยไม่มีแชท (แอปฮารุ / ตั้งเวลา)
 - ทุกรอบที่วนแก้ ให้เริ่มจากต้นฉบับสำรองเสมอ และสะสมกฎ/คำแก้ทั้งหมดไว้ในสคริปต์หรือไฟล์รายการเดียว
 - ไล่ดูภาพ "ทุกหน้า" ก่อนและหลังแก้ ไม่ใช่สุ่ม และตรวจด้วยสคริปต์คู่กัน
 - ตรวจคำสะกด/เนื้อหาให้ครบทุกย่อหน้าและทุกเซลล์ภาษาไทย เอกสารยาวแบ่งตรวจคู่ขนานได้ แต่ต้องรวมผลก่อนแก้ และตรวจรอบสองหลังแก้
 - สิ่งที่ได้ตอนจบ: .docx ที่แก้แล้ว + PDF ทุกเล่ม, สรุปการแก้, รายการสีแดง, จุดแปลก, กลุ่ม C — ทั้งหมดเป็นภาษาไทย

# ไฟล์ / การบันทึก
SAVE_MODE          = ทับไฟล์เดิม โดยสำรองต้นฉบับไว้ในโฟลเดอร์ `สำรองต้นฉบับ_ก่อนจัดรูปแบบ` ข้างไฟล์ก่อนเสมอ
REFERENCE          = เล่มเก่าที่จัดถูกแล้ว (ถ้ามี) ใช้เทียบค่าที่เขียนว่า "ตามไฟล์ต้นแบบ"

# หน้ากระดาษ (standard.page_margins_cm) — TOR/ลูกค้ากำหนดต่างจากนี้ ให้ใช้ตามนั้น
PAPER              = A4 แนวตั้ง (แนวนอนคงแนวนอน ใช้ขอบชุดเดียวกัน)
MARGIN             = บน 2.54 · ล่าง 2.54 · ซ้าย 2.54 (เว้นไว้เข้าเล่ม ห้ามตารางล้ำ) · ขวา 1.6 ซม.
HEADER / FOOTER    = หัวกระดาษห่างขอบ 0.96 ซม. · ท้ายกระดาษ 1.25 ซม.
COVER              = ห้ามเปลี่ยนขอบกระดาษ/ขนาดของหน้าปก (รูปพื้นหลังปกอิงขอบกระดาษ เปลี่ยนแล้วเกิดแถบขาว)

# ตัวอักษร
FONT               = TH SarabunPSK ทั้งเล่ม ทั้ง Latin และ Complex Script (font_replace: TH Sarabun New → TH SarabunPSK)
FONT_CODE          = Consolas / Courier / Mono เฉพาะโค้ด JSON SQL (code_fonts) ห้ามเปลี่ยนเป็นฟอนต์ไทย
FONT_KEEP          = Segoe UI Symbol, Cambria Math (ฟอนต์สัญลักษณ์)
BODY               = 16 pt (standard.styles.Normal)
CHAPTER (หัวข้อ 1) = 20 pt หนา กึ่งกลาง ขึ้นหน้าใหม่ (heading 1)
หัวข้อ 2           = 16 pt หนา ชิดซ้าย · หัวข้อ 3–4 = 16 pt ไม่หนา ชิดซ้าย
TOC                = หัว "สารบัญ" 20 pt หนา กึ่งกลาง · รายการ 16 pt (toc 1 หนา)
CAPTION            = 16 pt ไม่เอียง · ชื่อตารางอยู่ "เหนือ" ตาราง ชิดซ้าย · ชื่อรูปอยู่ "ใต้" รูป กึ่งกลาง
TABLE              = 14 pt (ห้ามเล็กกว่า 14 ยกเว้นเล่มผลทดสอบตามกฎใน SKILL.md) · ตาราง 7+ คอลัมน์ 14 pt (dense_table_font_pt)
PAGE_NUMBER        = ท้ายกระดาษ ชิดขวา 16 pt (page_number_align, page_number_font_size) เติมให้ถ้าไม่มี
NO_ITALIC          = ห้ามมีตัวเอียงทั้งเล่ม (no_italic) รวมคำบรรยายรูป/ตาราง ทั้ง Latin และ Complex Script
KEEP_RED_TEXT      = ข้อความสีแดงคงไว้ ห้ามเปลี่ยนสี/ข้อความ แต่ต้องรายงานว่าอยู่หน้าไหน (keep_red_text)

# ย่อหน้า
ALIGN              = กระจายแบบไทย (thaiDistribute) ทั้งเนื้อหา bullet รายการเลข และข้อความในเซลล์ตาราง (body_align, table_cell_align)
                     ไม่ใช้กับ: หัวข้อ สารบัญ คำบรรยาย หน้าปก โค้ด ย่อหน้าที่ตั้งกึ่งกลาง/ชิดขวา ย่อหน้าไม่มีอักษรไทย (ใช้ "เต็มบรรทัด")
                     **ห้ามถอยไปชิดซ้ายเพื่อแก้ตัวอักษรถ่าง** ให้แก้ด้วยจุดตัดคำ/รวมย่อหน้า/ขยายคอลัมน์ตาม "วิธีคิด" ใน SKILL.md
                     คอลัมน์ป้ายสั้น (เช่น "ส่วนของระบบ", "หัวข้อ") จัดกึ่งกลาง ทั้งตารางชนิดเดียวกันทั้งเล่ม
FIRST_LINE_INDENT  = 0.75 ซม. (standard.styles.Normal.first_line_cm)
LINE_SPACING       = 1.0 (Single) · ก่อน/หลังย่อหน้า 0 pt (หัวข้อ 1: ก่อน 18 หลัง 4 · หัวข้อ 2: ก่อน 8 หลัง 4)
MAX_EMPTY_LINES    = 1 (max_empty_lines) ยกเว้นหน้าปก
TEXT_FLOW          = ประโยคติดกัน เรียงสวยชิดขอบ ทั้งในและนอกตาราง (ผลเดียวกับก็อปไปวางแบบข้อความล้วน)
                     1) ย่อหน้าในเซลล์ที่ถูกตัดกลางประโยค → รวมเป็นย่อหน้าเดียว (merge_broken_paragraphs_in_cells)
                     2) นอกตาราง **ไม่รวม** ย่อหน้า (merge_broken_paragraphs_in_body = false) เคยรวม "จากปัญหา…" ผิด
                     3) Shift+Enter กลางประโยค → ช่องว่าง (join_soft_breaks_in_cells / _in_body) คงไว้ถ้าบรรทัดถัดไปเป็นเลขข้อ/bullet,
                        บรรทัดก่อนจบด้วย ":", ข้อความไม่มีอักษรไทย หรือฟอนต์โค้ด
                     4) ติดป้ายข้อความไทย `<w:cs/>` ทุก run ที่มีอักษรไทย แยกคำอังกฤษ/ตัวเลข (tag_thai_text) — Word บน Mac ต้องมีถึงตัดคำไทยถูก
                        พร้อมตั้ง szCs = ขนาดจริง และ bCs ถ้าตัวหนา

# ตาราง
TABLE_WIDTH        = ทุกตารางเต็มความกว้างถึงขอบขวา (widen_tables_to_text) ตาราง 7+ คอลัมน์ขยายไปทางขวาได้ เหลือห่างขอบกระดาษ ≥ 1 ซม.
TABLE_HEADER_REPEAT= ตารางข้ามหน้าต้องมีหัวซ้ำทุกหน้า และหัว + 2 แถวแรกอยู่หน้าเดียวกัน (keep_header_plus_rows)
TABLE_ROW_NO_SPLIT = แถวเดียวห้ามขาดครึ่งข้ามหน้า (ยกเว้นแถวที่สูงเกินหนึ่งหน้า)
TABLE_KEEP_WHOLE   = ตาราง ≤ 8 แถว และ < 2,000 ตัวอักษร อยู่หน้าเดียวทั้งตาราง (keep_whole_table_max_rows, keep_whole_table_max_chars)
                     ตั้งสูงกว่านี้ไม่ได้ เพราะแก้ใน Word แล้วหน้าเด้งทั้งก้อน · ห้ามผูกตารางที่ครอบสารบัญ และตารางที่มีรูป
TABLE_PADDING      = ระยะขอบในเซลล์ 5.4 pt ตัวอักษรห้ามชิดเส้น (table_cell_padding_pt)
TABLE_ROW_WIDTH    = ทุกแถวกว้างเท่ากัน ขอบขวาตรงกัน (equalize_row_width)
TABLE_BORDER       = เส้นครบทุกด้าน สีดำ 0.5 pt (table_border_pt, thin_border_to_black) ยกเว้นสีที่ตั้งใจ เช่น กรอบกล่องโค้ด D0D7DE (keep_border_colors)
COLUMN_WIDTH       = ปรับความกว้างคอลัมน์อัตโนมัติ: ปิดไว้ (balance_column_widths = false) เปิดต้องถามผู้ใช้ก่อน
CAPTION_AUTONUMBER = ใช้ฟิลด์ SEQ ให้สารบัญรูป/ตารางอัปเดตเอง ยกเว้นเนื้อหาอ้าง "ตาราง N" ไว้ ให้คงเลขเดิมแล้วแจ้ง

LANGUAGE_UI        = ทุกข้อความที่ตอบ สรุป คำถาม ปุ่ม และรายการงาน เป็นภาษาไทย

ขั้นที่ 0 เตรียมไฟล์
 - สำรองไฟล์ต้นฉบับก่อนแตะอะไรทั้งสิ้น
 - เช็กว่าไฟล์ไม่ได้เปิดค้างใน Word (มีไฟล์ ~$ชื่อไฟล์) ถ้าเปิดอยู่ให้แจ้งผู้ใช้ก่อน
 - ทำงานบนสำเนาเสมอ เสร็จและตรวจผ่านแล้วค่อยบันทึกตาม SAVE_MODE

ขั้นที่ 1 สำรวจไฟล์ต้นแบบ (ถ้ามี)
 - เปิดเล่มเก่า 2–3 เล่ม สรุป: ฟอนต์ ขนาด (เนื้อหา/หัวข้อแต่ละระดับ/ตาราง/คำบรรยาย) ระยะขอบ ระยะบรรทัด การจัดแนว ย่อหน้า
   หัวตาราง หัว/ท้ายกระดาษ เลขหน้า การขึ้นหน้าใหม่ตามบท
 - ค่าที่เขียนว่า "ตามไฟล์ต้นแบบ" ให้ใช้ค่าที่พบบ่อยที่สุดในเล่มเก่า แล้วบอกผู้ใช้ว่าใช้ค่าอะไร
 - ดูโครงหน้าแรก ๆ: ถ้า section แรกมีหลายหน้า (ปก → ทะเบียนคุมเวอร์ชัน → ตาราง TOR) ปกคือหน้า 1 หน้าเดียว

ขั้นที่ 2 ตรวจรูปแบบไฟล์ที่ต้องแก้ (ก่อนแก้)
 - Export เป็น PDF ด้วย Word (ให้เลขหน้าตรงของจริง) แล้วแปลงเป็นภาพย่อดูทุกหน้า
 - วัดสถิติ: จำนวนหน้า/ตาราง/รูป, ฟอนต์ที่ใช้จริงทุกตัว, ตารางที่ข้ามหน้าแต่ไม่มีหัวซ้ำ, หัวข้อค้างท้ายหน้า, หน้าว่าง, บรรทัดว่างติดกัน
 - จดปัญหาที่เห็นด้วยตา โดยเฉพาะ:
   • ตัวอักษรถูกถ่างเต็มบรรทัด ("ป  ร  ะ  เ  ท  ศ") จาก Shift+Enter กลางย่อหน้าที่จัดกระจาย หรือระยะตัวอักษรที่บีบด้วยมือ
   • ฟอนต์ปนกัน หรือฟอนต์ที่เครื่องไม่มี
   • หัวตารางพิมพ์ซ้ำเองกลางตาราง
   • หัวข้อหรือชื่อ API หลุดเข้าไปอยู่ในเซลล์ตาราง (สองตารางติดกันเป็นตารางเดียว)
   • รูปกับคำบรรยายอยู่ในย่อหน้าเดียวกัน (รูปหลุดเข้าสารบัญรูป)
   • สารบัญพิมพ์เอง (ไม่ใช่ฟิลด์) หรือหัว "สารบัญ" ดันขึ้นหน้าใหม่ด้วย Enter
   • ไม่มีเลขหน้า หรือเลขหน้าเริ่มผิด
   • ตารางโค้ด/JSON ถูกตัดข้ามหน้าเหลือไม่กี่บรรทัด

ขั้นที่ 3 แก้รูปแบบ (ทำบนสำเนา)
 1) เปลี่ยนฟอนต์ทุกตัวเป็น FONT (ทั้ง Latin/Complex Script/Style) ยกเว้น FONT_CODE และ FONT_KEEP
 2) ตั้งขนาด/ตัวหนา/ระยะ ตาม [1] ผ่าน "Style" (หัวเรื่อง 1–4, ปกติ, คำอธิบายภาพ, สารบัญ 1–3) ไม่ไล่จัดทีละย่อหน้า
    ห้ามแตะ Style หัวเรื่องในตัว (heading 1–4) ถ้าค่าถูกอยู่แล้ว — Word จะผูกรายการเลขกลับเข้ามา
 3) ลบ Shift+Enter กลางย่อหน้าที่จัดกระจายหรือเต็มบรรทัด (ยกเว้นในโค้ด และบรรทัดที่ตั้งใจตัด เช่น ชื่อโครงการบนปก)
    และเปิด "Don't expand character spaces on a line ending with SHIFT+RETURN"
 4) ลดบรรทัดว่างติดกันให้เหลือไม่เกิน MAX_EMPTY_LINES (ยกเว้นหน้าปก)
 5) บท/สารบัญ: ตั้ง Page break before และลบบรรทัดว่างหรือ page break ที่ใช้ดันหน้าก่อนหน้านั้น
 6) หัวข้อทุกระดับ Keep with next + Keep lines together (ยกเว้นย่อหน้ามีเลขที่ยาว เช่น "2.4.1 …" ไม่ผูกกับย่อหน้าถัดไป)
 7) ตาราง: ตั้ง "Repeat as header row" ให้แถวหัว (แถวแรกพื้นสี/ตัวหนา หรือหัวหลายแถว) · ลบหัวที่พิมพ์ซ้ำกลางตาราง ·
    ห้ามแถวขาดข้ามหน้า · TABLE_KEEP_WHOLE · หัว + 2 แถวแรกอยู่หน้าเดียวกัน · คำบรรยายเหนือตาราง Keep with next
 8) รูป: "หัวข้อ + คำอธิบายสั้นก่อนรูป + รูป + คำบรรยาย" อยู่หน้าเดียวกัน (คำอธิบายยาวเกิน ~900 ตัวอักษรยอมให้แยก: figure_intro_max_chars)
    รูปกับคำบรรยายอยู่ย่อหน้าเดียวกันให้แยก · คำบรรยายรูปทุกรูปรูปแบบเดียวกัน
 9) ตัวเอียง: ปลดทั้งเล่ม ทั้งใน Style และที่จัดตรง (Italic และ ItalicBi) รวมหัว/ท้ายกระดาษ แล้วตรวจซ้ำ
 10) ตาราง "เล็ก" ที่ตั้งให้อยู่หน้าเดียว แต่สูงเกินหนึ่งหน้า ต้องปลดให้ตัดข้ามหน้าได้ (และมีหัวซ้ำ)
 11) เส้นตารางทั้งเล่มแบบเดียวกัน ตารางไม่มีเส้น (ยกเว้นกล่องโค้ดคอลัมน์เดียว) ให้ใส่เส้น — ถ้าเส้นหายให้เช็กก่อนว่าเป็นตารางหรือรูป
 12) ลบ bullet ว่างนอกตาราง (คอลัมน์ "NO/ลำดับ" ที่ใช้เลขอัตโนมัติในตาราง ห้ามลบ)
 13) สีแดง ไฮไลต์ คอมเมนต์ Track changes: ห้ามเปลี่ยน ให้ทำรายการ ไฟล์ / หน้า / ข้อความ แล้วรายงาน
 14) ทุกตาราง: ระยะขอบในเซลล์ตาม TABLE_PADDING, ลบช่องว่างที่ขึ้นต้นข้อความในเซลล์, ทุกแถวกว้างเท่ากัน, เส้นครบรวมเส้นบนของแถวหัว
 15) หน้าปก: ย่อหน้าโลโก้ที่ถูกตั้งเป็นรายการ (มีจุดดำหน้ารูป) → เอารูปแบบรายการออก จัดกึ่งกลาง (fix_cover_bullet_dot)
 16) ตารางหัว/เนื้อหาที่แยกเป็นสองตาราง → รวมเป็นตารางเดียว (คอลัมน์เท่ากัน ตารางแรกมีหัว ตารางที่สองไม่มีหัว) แล้วตั้งหัวซ้ำ
     ฟอนต์ในตารางให้แบบเดียว และใช้กระจายแบบไทยตาม ALIGN (ห้ามถอยไปชิดซ้าย)
 17) แก้ไขได้ปกติ: Keep with next เท่าที่จำเป็น — หัวข้อ→ย่อหน้าถัดไป, หัวข้อ+คำอธิบาย→รูป→คำบรรยาย, คำบรรยาย→ตาราง, หัว+2 แถวแรก,
     ตารางสั้นตาม TABLE_KEEP_WHOLE · ห้ามผูกทั้งตารางใหญ่ ห้ามดันหน้าด้วย Enter ห้ามตั้งความสูงแถวแบบ Exactly
     ทดสอบ: พิมพ์/ลบกลางหน้าที่มีตาราง แล้วเนื้อหาต้องไม่กระโดดทั้งก้อน
 18) หัวข้อที่หลุดเข้าไปในเซลล์ตาราง: แยกตาราง แล้วย้ายหัวข้อออกมาเป็นย่อหน้าปกติด้วย Style หัวข้อเดิม
 19) สารบัญ/สารบัญรูป/สารบัญตาราง ที่พิมพ์เอง: แทนด้วยฟิลด์ (TOC, Table of Figures) แล้ว Update ทั้งตาราง
 20) ท้ายสุด: Update fields ทั้งเล่ม → Repaginate → Update TOC ทั้งตาราง → Update page numbers อีกรอบ

ขั้นที่ 4 ตรวจเนื้อหาและคำผิด
 อ่านทุกย่อหน้า (ไม่ใช่สุ่ม) แล้วแยกผลเป็น 3 กลุ่ม:
 A. คำผิดที่มั่นใจ → แก้เลย (Find/Replace แบบตรงตัว Match case และนับจุดที่แก้ · เริ่มจาก `common-replacements.tsv`)
    • สะกดผิด/วรรณยุกต์ผิด/คำซ้ำ (เว็ป→เว็บ, อินเตอร์เน็ต→อินเทอร์เน็ต, อีเมลล์→อีเมล, สถานะภาพ→สถานภาพ)
    • เว้นวรรคเกิน/ขาด, ช่องว่างแทรกกลางชื่อคีย์หรือ path ("SMTP_ USERNAME", "/ {id}")
    • ยัติภังค์หลงเหลือจากการตัดคำ ("ไม่ผ่าน-การตรวจ")
    • วงเล็บติดคำ "คำ(ข้อความ)" → "คำ (ข้อความ)", ไม้ยมก "ต่างๆ" → "ต่าง ๆ"
 B. ปัญหาที่แก้ได้โดยไม่ต้องเดา → แก้และบอกผู้ใช้
    • ย่อหน้า/ข้อที่วางซ้ำทุกตัวอักษร (remove_duplicate_paragraphs) · เลขลำดับรายการซ้ำ (1, 2, 2, 4)
 C. ปัญหาที่ต้องให้คนตัดสิน → ห้ามแก้เอง ทำรายการพร้อมตำแหน่ง (หัวข้อ/หน้า)
    • บท/หัวข้อที่ไม่มีเนื้อหา, ตาราง/รูปที่ไม่มีคำบรรยายหรือเลขขาด
    • ข้อมูลขัดกันระหว่างเล่ม (URL, เลขเวอร์ชัน, จำนวน, ชื่อระบบ)
    • รายการในบทสรุปไม่ตรงกับรายละเอียด (เทียบรหัส Method Endpoint ทีละรายการ)
    • ประโยคอ่านไม่เข้าใจ ภาษาพูด หรือข้อความลอกจากเอกสารนักพัฒนา (README, emoji, คำสั่งถึง dev)
    • สิทธิ์/ค่าตั้งต้นที่ดูไม่สมเหตุสมผล
    • **ความสม่ำเสมอ** (`check_consistency.mjs` รายงานในไฟล์สรุปหัวข้อ "ควรเช็คเนื้อหา"):
      ช่องว่างคู่ในเนื้อหา/ตาราง (มักเกิดจากลบสัญลักษณ์ เช่น "→" แล้วเหลือช่องว่าง) ·
      ตัวคั่นที่ใช้ไม่เหมือนกันในคอลัมน์เดียวกัน · การอ้างข้อ TOR เดียวกันหลายแบบ (เช่น "5.5 ลำดับที่ 6" กับ "5.5")
      ให้ผู้ใช้เลือกแบบเดียวทั้งเล่ม ถ้าเปลี่ยนสัญลักษณ์ให้เปลี่ยนทุกจุด ไม่ลบทิ้งบางจุด
 ห้ามแก้: GLOSSARY_KEEP, ห้ามแต่งเนื้อหาใหม่ที่ไม่มีในต้นฉบับ
 มีหลายเล่มในโครงการเดียวกัน ให้เทียบชื่อโครงการ ชื่อระบบ URL หัวกระดาษ ระหว่างเล่มด้วย

 โหมดแก้ทุกจุด ("แก้ทุกจุด" / "แก้หมด" / "แก้เนื้อหาด้วย" / "แก้ตามที่แจ้งมาทั้งหมด" / "แก้ข้อ ...") — แก้กลุ่ม B และ C ด้วย:
    • หาค่าที่ถูกจากหลักฐานในเอกสารก่อนเสมอ: ตารางรายละเอียด/สเปก > เนื้อหา > บทสรุป/สารบัญ
      เท่ากันใช้ค่าที่ปรากฏบ่อยกว่า ข้ามเล่มใช้เล่มที่เป็นแหล่งหลักของเรื่องนั้น (Endpoint → เล่ม API, เครื่อง → Architecture, ผลทดสอบ → เล่มทดสอบ)
    • คำสะกดไม่แน่ใจ → ใช้รูปที่ถูกตามราชบัณฑิตฯ หรือรูปที่เล่มใช้มากที่สุด
    • ชื่อเรียกไม่สม่ำเสมอ (ล็อกอิน/Login/เข้าสู่ระบบ) → แบบที่ใช้มากที่สุดทั้งเล่ม ยกเว้นในโค้ดและชื่อปุ่มที่อ้างหน้าจอจริง
    • ประโยคอ่านไม่เข้าใจ/ภาษาพูด/ข้อความถึงนักพัฒนา/emoji → เรียบเรียงเป็นภาษาเขียนทางการ สั้นที่สุด คงความหมายและศัพท์เทคนิค
    • บท/หัวข้อไม่มีเนื้อหา → ลบหัวข้อ เลื่อนเลข แก้คำอ้างอิง "ดูหัวข้อ x.y" (ห้ามแต่งเนื้อหาเติม)
      เลขอัตโนมัติจะเลื่อนเอง แต่เลขที่ "พิมพ์เอง" ("4.3 โครงสร้างฐานข้อมูล", "หัวข้อ 3.4") ต้องแก้ตามด้วย
    • รูป/ตารางไม่มีคำบรรยายหรือเลขขาด/ซ้ำ → ใส่คำบรรยายจากหัวข้อเหนือรูป เรียงเลขใหม่ทั้งเล่ม แก้คำอ้างอิงตาม
    • สารบัญ/บทสรุปไม่ตรงรายละเอียด → แก้ฝั่งสรุปให้ตรงรายละเอียด
    • สิทธิ์/ค่าตั้งต้นที่ดูไม่สมเหตุสมผล → แก้เฉพาะถ้ามีจุดอื่นในเอกสารระบุค่าที่ถูก ไม่งั้นรายงาน
 ยังไม่แตะแม้ในโหมดนี้ (รายงานพร้อมเหตุผล): ข้อความสีแดง · โค้ด SQL JSON ในกล่องโค้ด และ GLOSSARY_KEEP · ตัวเลข/ข้อมูลที่ไม่มีหลักฐาน
 บันทึกทุกจุดที่แก้เนื้อหา: เล่ม / หน้า / เดิม → ใหม่ / เหตุผล ใส่ในสรุปหัวข้อ "เนื้อหาที่แก้ให้"
 สั่งแก้หลังส่งงานไปแล้ว → เริ่มจากต้นฉบับสำรอง รวมคำแก้รอบก่อน + ใหม่ แล้วรันใหม่ทั้งเล่ม

ขั้นที่ 5 ทดสอบผลลัพธ์ (ต้องผ่านทุกข้อก่อนบันทึก)
 - Export PDF ใหม่ ดูภาพย่อทุกหน้าเทียบกับก่อนแก้ · ซูมดูหน้าปก หน้า 2 (ทะเบียนคุมเวอร์ชันต้องคง 16 pt) สารบัญ และหน้าแรกของแต่ละบท
 - ตารางที่ข้ามหน้าแต่ไม่มีหัวซ้ำ = 0 · ตารางข้อมูลสั้นไม่ถูกตัดครึ่ง
 - ไม่มีหัวข้อหรือคำบรรยายตารางค้างท้ายหน้า, ไม่มีหน้าว่าง, ไม่มีตัวอักษรถ่างเต็มบรรทัด, ไม่มีช่องว่างครึ่งหน้ากลางบท
 - ฟอนต์มีแค่ FONT + FONT_CODE + FONT_KEEP · ไม่มีตัวเอียง · เส้นตารางดำ 0.5 pt ทุกเส้น
 - สารบัญเลขหน้าตรง (สุ่ม 5 รายการ) มีแต่หัวข้อ ไม่มีย่อหน้าเนื้อหา และเริ่มต่อจากหัว "สารบัญ" ในหน้าเดียวกัน
 - เลขหัวข้อตรงต้นฉบับ (`check-numbers.ps1` ขึ้น NUMBERS-PROBLEM ห้ามส่ง) ไม่มี "ส่วน 2.03", "บทความ I." งอก
 - จำนวนตาราง/รูปไม่หาย และข้อความไม่หาย (เทียบจำนวนตัวอักษร/ช่องว่างก่อน-หลังด้วย dump-text)
 - หัวข้อ/คำอธิบายกับรูปของมันอยู่หน้าเดียวกันทุกรูป · คำบรรยายมีเว้นวรรคหลังเลข ("ตารางที่ 14 ชื่อ")
 - ไม่มี bullet ว่าง · ข้อความสีแดงยังอยู่ครบและมีรายการตำแหน่ง · หน้าปกไม่มีจุด/สัญลักษณ์แปลกปลอม
 - ตารางขอบขวาตรงกันทุกแถว เส้นครบ ตัวอักษรไม่ชิดเส้น ไม่ล้นขอบกระดาษ
 - ลองพิมพ์/ลบใน Word แล้วหน้าไม่เด้ง
 - ข้อไหนไม่ผ่าน แก้แล้วทดสอบซ้ำ ห้ามรายงานว่าเสร็จถ้ายังไม่ผ่าน

## ทำงานกับผู้ใช้
 - ทุกรอบที่แก้เพิ่ม ให้รันใหม่จาก "ต้นฉบับสำรอง" เสมอ (ไม่แก้ทับผลรอบก่อน)
 - ไฟล์ใหญ่ (หลายร้อยหน้า/พันตาราง) รอบละ ~10 นาที บอกล่วงหน้าว่านานเพราะอะไร และรายงานความคืบหน้า
 - ผู้ใช้ส่งภาพหน้าจอชี้จุด → หาสาเหตุ ตอบก่อน แล้วแก้แบบ "ทั้งเล่ม" ไม่ใช่แค่จุดนั้น แล้วเพิ่มกฎลงไฟล์นี้
 - ผู้ใช้เปลี่ยนใจ (เช่น สีแดงให้คงไว้) → ย้อนการแก้นั้นทั้งหมด และอัปเดตกฎ
 - ผู้ใช้แก้เล่มเอง แล้วสั่งให้เอามาปรับสกิล → เทียบไฟล์ของผู้ใช้กับผลของสกิล ทุกจุดที่ต่างให้ตัดสินว่า
   เป็นข้อผิดของสกิล (แก้สคริปต์) เป็นความชอบของผู้ใช้ (เพิ่มกฎ) หรือผู้ใช้พลาด (เพิ่มการตรวจ) แล้วทดสอบกับสำเนาไฟล์ของผู้ใช้
 - สั่งจากแชทต้องใส่ `-Open` เสมอ ผู้ใช้รอดูหน้าติดตามงานเด้งขึ้นมา

## Word และสคริปต์
 - ใช้ Word ได้ทีละงาน อย่ารันสคริปต์ Word สองตัวพร้อมกัน (New-Object Word.Application อาจได้ instance เดียวกัน)
 - สคริปต์ค้าง ให้ปิดเฉพาะ WINWORD ที่สคริปต์เปิด ห้ามปิด Word ที่ผู้ใช้เปิดอยู่
 - Word เปิดผ่านสคริปต์ไม่ได้ (OFFICE_MODULE_VERSION_MISMATCH ตอน Office อัปเดต) → หยุด ให้ผู้ใช้เปิด Word เองหนึ่งครั้งหรือรีสตาร์ต
   (ถ้ามีกล่อง "กู้คืนเอกสาร" เลือก "ไม่ ให้เอาไฟล์เหล่านี้ออก") ห้ามบันทึกไฟล์ที่ทำไม่ครบทับของเดิม
 - ไฟล์สคริปต์ PowerShell ที่มีภาษาไทยต้องบันทึกเป็น UTF-8 with BOM ไม่งั้นข้อความไทยเพี้ยน และ Find หาไม่เจอโดยไม่ขึ้น error
 - ฟอนต์ที่เครื่องไม่มี Word จะแทนด้วยฟอนต์อื่นตอน export แต่ใน XML ยังเป็นชื่อเดิม → เปลี่ยนชื่อฟอนต์ใน XML (document/styles/header/footer)
 - ลูป Find ต้องมีตัวกันวนไม่รู้จบ และเช็กว่าตำแหน่งยังอยู่ในช่วงที่ตั้งใจ
 - dump ข้อความเป็น txt: เครื่องหมายจบตาราง (\r\a) อาจทำให้หัวข้อที่อยู่ "ถัดจาก" ตารางดูเหมือนอยู่ "ใน" ตาราง
   ต้องยืนยันด้วย Range.Information(wdWithInTable) ก่อนแก้
 - Range.Information(3) คือเลขหน้าของ "ปลาย" ช่วง ถ้าต้องการหน้าเริ่ม ให้ยุบช่วงไปที่จุดเริ่มก่อน
 - หลัง Word บันทึก ให้เทียบ Style หัวเรื่องกับต้นฉบับ: มีเลขรายการอัตโนมัติงอก (เช่น "ส่วน 2.03" ในสารบัญ) ให้เอาออก
   ปิดเลขรายย่อหน้าเท่านั้น ห้ามลบเลขออกจาก Style ทั้ง Style (เลขจริง "1.1" มาจาก numbering ที่ผูกกับ Style)
 - ตาราง > 1,000 ตารางใช้เวลานาน ให้รันเบื้องหลังและพิมพ์ความคืบหน้าทุก 200 ตาราง
 - ทุกครั้งที่เพิ่มกฎปรับตาราง ให้ render แล้วดูตารางหลายแบบ (หัวหลายแถว, เซลล์ผสาน, กล่องโค้ด) ก่อนรันเล่มใหญ่

## ปก และหน้าแรก ๆ
 - **ปกคือหน้าแรกหน้าเดียว:** เล่มที่ section แรกยาวหลายหน้า (ปก → ทะเบียนคุมเวอร์ชัน → ตาราง TOR) ห้ามขยายตัวอักษรหน้า 2–3
   (`cover_size_fix.mjs` หยุดที่ตัวขึ้นหน้าใหม่ตัวแรกแล้ว — เคยขยายหัว "ทะเบียนคุมเวอร์ชั่นเอกสาร" เป็น 24 pt ผิด)
 - ชื่อโครงการยาวเกินหนึ่งบรรทัดที่จัดกึ่งกลาง (ปก หน้าตาราง TOR) ให้ขึ้นบรรทัดใหม่ก่อนคำเชื่อมวลี (พร้อม / ภายใต้ / สำหรับ)
   แทนการปล่อยให้ Word ตัดเอง เช่น "โครงการจัดหาผู้ให้บริการสิทธิ์การใช้งาน" / "พร้อมการบำรุงรักษาภายใต้โครงการ…"
 - จุดดำบนปก = ย่อหน้าโลโก้ถูกตั้งเป็นรายการ bullet

## ตาราง
 - ขอบขวาตารางเป็นขั้นบันได มักเกิดจาก gridAfter/wAfter ในแถว → ให้ช่องว่างนั้นกับเซลล์สุดท้าย เช็กทุกเล่ม
 - ตารางหัว/เนื้อหาแยกกัน อาจมีย่อหน้าว่างหรือ page break คั่น และจำนวนคอลัมน์ใน grid อาจต่างกันนิดเดียว → เทียบจำนวนเซลล์ของแถวส่วนใหญ่
 - ปรับความกว้างแถวให้เท่ากัน: ห้ามกว้างเกินพื้นที่พิมพ์ และห้ามทำกับตารางที่มีเซลล์ผสานแนวตั้ง (เช่น Use Case)
   เพราะแถวพวกนั้นดูแคบกว่าความจริง แล้วถูกยืดจนล้นขอบ → ตารางแบบนั้นให้แค่ดึงกลับเข้าขอบถ้าล้น
 - ย่อหน้าในเซลล์ที่ใช้ Style หัวเรื่อง (เช่น "Test ID" เป็น Heading 1) ห้ามนับเป็นบท/หัวข้อ ไม่งั้นขึ้นหน้าใหม่ก่อนตาราง
 - ห้ามผูก Keep with next แถวข้อมูลเข้ากับแถวที่มีรูป/ภาพหน้าจอ รวมกันแล้วสูงเกินหน้า ทำให้หัวข้อค้างหน้าเปล่า
 - ผูกทั้งตารางแล้วต้อง Repaginate ตรวจซ้ำว่าตารางยังสูงไม่เกินหนึ่งหน้า
 - **ห้ามผูกตารางที่ครอบสารบัญ** (บางเล่มวางหัว "สารบัญ" กับฟิลด์ TOC ไว้ในตาราง) ไม่งั้นสารบัญทั้งก้อนหลุดไปหน้าถัดไป เหลือหน้าว่าง
 - เส้นตารางสีอ่อน (#AAAAAA, #A6B8CC) หรือบาง 0.25 pt ถือว่า "เส้นหาย" → แก้ใน XML (w:sz="4" w:color="000000") เร็วกว่าตั้งผ่าน Word มาก
 - ตารางโค้ด/JSON ที่ยาวเกินหนึ่งหน้าและไม่มีหัว ไม่ต้องตั้งหัวซ้ำ (ไม่นับเป็นข้อผิดพลาด)
 - ห้ามใช้ regex แบบ "ตั้งแต่ <w:tc> ไปจนเจอ <w:t> ที่ขึ้นต้นด้วยช่องว่าง" เพื่อลบช่องว่างนำหน้าในเซลล์
   มันข้ามไปลบช่องว่างกลางเซลล์ ("ไม่มี Token" → "ไม่มีToken") เคยหายนับพันจุด → หลังแก้เทียบจำนวนช่องว่างก่อน/หลังทุกครั้ง

## สารบัญ คำบรรยาย และหน้าว่าง
 - หน้าว่างมักเกิดจาก (1) หัวข้อที่มี page break (\f) อยู่แล้วแต่ตั้ง Page break before ซ้ำ
   (2) ย่อหน้าว่างหลังตารางยาวหรือหลังสารบัญล้นไปอยู่หน้าใหม่คนเดียว → ลบ (ถ้าอยู่ระหว่างสองตารางห้ามลบ ให้ย่อเหลือ 1 pt)
 - เปลี่ยนเลขคำบรรยายเป็น SEQ จะเรียงเลขใหม่ ถ้าเนื้อหาอ้าง "ตาราง N" ไว้ หรือเลขเริ่มไม่ใช่ 1 ให้คงเลขเดิม
 - แทนเลขคำบรรยายด้วย SEQ อย่ากินช่องว่างหลังเลข (จะได้ "ตารางที่ 14บันทึก...")
